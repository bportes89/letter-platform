Visão geral

Prisma Studio é um orquestrador multi-cliente de APIs de consulta brasileiras. Você integra uma API só e o sistema decide qual conector externo (Serasa, Receita, Detran, etc.) usar para cada tipo de consulta, aplicando preço, fallback e idempotência por cliente.

O que é

A API expõe execuções: cada chamada cria uma Execution que orquestra um ou mais conectores e devolve um resultado canônico em JSON. O mesmo resultado também pode ser baixado em PDF formatado, num segundo passo.

Conceitos centrais

  • Template — a consulta que você chama. Tem um template_id, uma lista de campos de entrada e um preço. É a unidade da API: POST /api/v1/executions/<template_id>/run/.
  • Bloco — cada chave de results. Um template entrega um ou mais blocos, e cada bloco tem um schema canônico de campos.
  • Execução — uma chamada. Identificada por um id (UUID v7), com status próprio e resultado disponível por 24 horas.
  • API key — credencial Bearer (psk_live_...). Veja Autenticação.
  • Webhook — endpoint da sua aplicação chamado quando uma execução conclui. Veja Webhooks.

Como funciona uma consulta

  1. Você chama POST /api/v1/executions/<template_id>/run/ com os campos da consulta no corpo.
  2. A plataforma escolhe o fornecedor, dispara a consulta e normaliza a resposta para o schema canônico de cada bloco.
  3. Devolve { id, status, results } — 200 com o resultado, ou 202 quando o template é assíncrono.
  4. No 202, sua aplicação busca em /api/v1/executions/<id>/result/ ou espera o webhook.

Cada template documenta o seu próprio caso em Templates.

Primeiros passos

Este guia leva você do zero a uma consulta executada com sucesso em três passos.

Gere sua API key

Acesse /settings/api-keys e clique em "Nova chave". Copie o valor mostrado uma vez — ele não é exibido novamente. O formato é psk_live_<32 caracteres>.

A chave é vinculada à sua conta. Trate como senha: nunca commit em repositório, nunca exponha em frontend.

Faça sua primeira consulta

Use seu cliente HTTP preferido. Exemplo com curl:

curl
curl -X POST https://api.prismafy.com.br/api/v1/executions/<id-de-um-template>/run/ \
  -H "Authorization: Bearer psk_live_xxxx..." \
  -H "Content-Type: application/json" \
  -d '{"cpf":"52998224725"}'

A execução é feita por template: o id do template vai na URL (você encontra os seus em Templates) e o body são só os campos da consulta. A resposta traz o resultado direto:

{
  "id": "01990000-0000-7000-8000-0000000000ee",
  "status": "success",
  "results": {
    "cpf-credito": { "score": 780, "faixa": "A" }
  }
}
  • results é indexado pelo slug do bloco, com o dado já normalizado.
  • Guarde o id — ele identifica esta execução.
  • Em template assíncrono a resposta é HTTP 202 com status: "running" e results vazio; a página do template diz qual é o caso do seu.

Veja tudo sobre a sua consulta

Cada template tem uma página com tudo que aquela consulta faz: os campos que ela aceita, os parâmetros opcionais (async, webhook_url, path_key), se a resposta vem no corpo ou em 202, o formato do que volta, como pegar o resultado e o PDF depois, os erros possíveis e o preço.

Abra Templates, escolha o seu e copie o cURL de lá — ele já vem com o template_id e os campos certos.

Para receber o resultado sem ficar perguntando, configure um webhook.

Autenticação

Toda chamada à API requer um header Authorization: Bearer <api-key>.

Formato da chave

Chaves de produção têm prefixo psk_live_ seguido de 32 caracteres alfanuméricos. Sandbox (futuro) usará psk_test_. A chave inteira tem ~40 caracteres e é case-sensitive.

Header obrigatório

Authorization: Bearer psk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Não envie a chave em query string ou body. Apenas no header Authorization.

Geração e revogação

Crie em /settings/api-keys. O valor é mostrado uma única vez no momento da criação — guarde imediatamente. Após isso o painel exibe apenas os primeiros caracteres mascarados.

Para revogar uma chave comprometida, use o botão "Revogar" no painel. A revogação é imediata: chamadas seguintes com a chave revogada retornam 401.

Você pode ter várias chaves ativas ao mesmo tempo (útil para separar ambientes da sua aplicação). Recomendamos uma chave por aplicação cliente para facilitar revogações pontuais.

Boas práticas

  • Armazene a chave em variável de ambiente, nunca no código.
  • Nunca exponha a chave em frontend público — toda chamada deve sair do seu servidor.
  • Em logs, mascare antes de imprimir (mostre apenas os primeiros 12 caracteres).
  • Rotacione chaves periodicamente (sugerido: a cada 90 dias para chaves de produção).

Erros

A API usa códigos HTTP padrão e devolve um envelope JSON consistente em todas as respostas de erro.

202Aceito; processamento assíncrono. Busque o resultado por polling ou espere o webhook.

Saldo insuficiente é 422, não 402. O code é insufficient_balance e nada é cobrado. O status 402 só aparece no resultado de um template de resposta direta cuja execução foi registrada nesse estado.

A lista de erros daquela rota, com o que fazer em cada um, está na página do template.

Formato dos erros

Todo erro retorna o mesmo envelope:

{
  "message": "Sem saldo disponível para esta consulta.",
  "code": "insufficient_balance",
  "field_errors": null
}
  • message — texto humano em pt-BR; pode mudar entre versões.
  • code — string snake_case estável; pode ser usado em lógica do cliente.
  • field_errors — objeto indexado pelo nome do campo; o valor é sempre uma lista de mensagens (um campo pode falhar mais de uma regra). Vem preenchido nos erros de validação e é null em todos os outros.
  • id — só aparece quando o erro já registrou uma execução: o 422 de input inválido (que grava a execução como invalid) e o 503 queue_unavailable (que cria, cobra e estorna antes de recusar). Nos demais erros a chave simplesmente não existe — ela não vem como null.

Não há chave details: o contexto do erro está em field_errors ou na message.

Erro de validação de input — é o envelope com as duas chaves extras:

{
  "message": "Input inválido para esta consulta.",
  "code": "validation_error",
  "field_errors": {
    "cpf": ["CPF inválido: o dígito verificador não confere."]
  },
  "id": "01990000-0000-7000-8000-0000000000ee"
}

Trate code como contrato e message como apresentação.

Toda resposta traz o cabeçalho X-Request-Id — cite-o ao falar com o suporte.

Idempotência

POSTs de execução — /api/v1/executions/<template_id>/run/ e o formato clássico /api/v1/executions/ — aceitam o header Idempotency-Key (alias aceito: X-Idempotency-Key). Qualquer string única por tentativa serve; recomendamos um UUID. Repetir a mesma chave com o mesmo corpo devolve a resposta original sem cobrar de novo; com corpo diferente devolve 422 idempotency_conflict; com a primeira chamada ainda rodando, 409 idempotency_in_progress (janela de 60 s).

Use sempre que possível: previne cobrança duplicada por retries em rede instável. A chave vale por 24 horas após a primeira chamada.

Webhooks

Configure um endpoint na sua aplicação para receber notificações quando execuções concluírem, em vez de fazer polling.

Configuração

Acesse /settings/webhook e cadastre o URL HTTPS do seu endpoint. O painel mostra o secret gerado uma vez — guarde para validar assinaturas.

Além dos endpoints cadastrados, cada execução pode pedir uma entrega extra: mande webhook_url no corpo da chamada (URL HTTPS pública). Ela recebe o mesmo payload, assinado com o mesmo segredo da conta, além dos endpoints cadastrados.

Evento disponível

  • execution.finished — a execução chegou a um status terminal. Use o campo status do payload para distinguir o desfecho: success, partial, failed, invalid, timeout ou insufficient_balance.

Ao cadastrar um webhook você pode assinar apenas alguns eventos; deixar a lista vazia recebe todos. Mais eventos podem ser adicionados no futuro — sempre filtre pelo campo event.

Formato do payload

Um POST application/json cujo body tem os campos no topo (sem envelope data):

{
  "event": "execution.finished",
  "id": "01990000-0000-7000-8000-0000000000ee",
  "status": "success",
  "results": {
    "cpf-credito": { "score": 780, "faixa": "A" }
  },
  "finished_at": "2026-05-05T13:42:13Z"
}

É o mesmo envelope que o POST /api/v1/executions/{template_id}/run/ devolve, acrescido de event e finished_at.

  • id — id da execução. Use para consultar o resultado de novo em GET /api/v1/executions/{id}/result/ e como chave de deduplicação.
  • status — desfecho da execução (veja a lista de eventos acima).
  • results — um objeto indexado pelo slug do bloco; o valor é o dado já normalizado para o schema canônico daquele bloco. Vazio quando a execução não entrega dado.
  • error — presente só quando o status indica falha; frase curta explicando o que houve.

Em templates de resposta direta o corpo entregue é o próprio dado, sem envelope: o id, o status e o horário chegam nos cabeçalhos X-Prisma-* (abaixo). Isso vale enquanto há dado a entregar (success e partial); quando a execução falha não há dado, e o corpo é { "id", "status", "error" } — o mesmo trio do envelope, sem results e sem event. Filtre pelo status do cabeçalho ou do corpo antes de tentar ler o dado.

O exemplo de payload do seu template está na página dele, em Templates.

Cabeçalhos

Cada entrega inclui:

  • X-Prisma-Event — o tipo do evento (execution.finished).
  • X-Prisma-Delivery-Id — id único desta tentativa de entrega.
  • X-Prisma-Execution-Id — id da execução.
  • X-Prisma-Status — o status da execução na hora da entrega.
  • X-Prisma-Finished-At — quando a execução terminou (ISO 8601; só quando já há horário de término).
  • X-Prisma-Signature — assinatura HMAC (quando há secret configurado).

Validação de assinatura

Quando o webhook tem secret, cada POST inclui o header X-Prisma-Signature no formato:

X-Prisma-Signature: sha256=<hex>

O <hex> é o HMAC-SHA256 do corpo bruto recebido (bytes exatos, não re-serialize o JSON) usando seu secret. Verifique antes de processar:

import hmac, hashlib

def is_valid(body_bytes: bytes, header: str, secret: str) -> bool:
    expected = hmac.new(secret.encode(), body_bytes, hashlib.sha256).hexdigest()
    return hmac.compare_digest(f"sha256={expected}", header)

Use comparação constant-time (hmac.compare_digest) para evitar timing attacks.

Política de retries

Respostas com status HTTP 2xx são consideradas entregues. Qualquer outra coisa dispara retry com backoff exponencial: 30s, 2min, 10min, 1h, 6h. Após 5 tentativas a entrega é marcada falhada e listada em /settings/webhook para reenvio manual.

Mantenha seu endpoint idempotente: a mesma execução pode chegar várias vezes. Use o id (ou o header X-Prisma-Delivery-Id) como chave de deduplicação.

Síncrono × assíncrono

Quando o resultado chega.

Este template responde 200 com o resultado no corpo. Para não esperar, mande "async": true e receba 202 na hora.

Tempo máximo estimado da cadeia
30 s
Teto do servidor
180 s

O teto é da conexão, não da cadeia: passando dele o servidor corta a resposta e a chamada volta sem o resultado. A execução não para — ela termina do nosso lado, e a cobrança continua de pé (o estorno só vem quando o desfecho é failed ou invalid).

Para recuperar o resultado, repita a chamada com a mesma Idempotency-Key: enquanto a primeira ainda roda a resposta é 409 idempotency_in_progress; depois que ela termina, a repetição devolve a resposta original sem cobrar de novo. Sem a chave, a execução está em Análise, no painel, com o id para GET /executions/<id>/result/. Cadeia perto do teto pede "async": true.

Cadeia longa

O tempo estimado desta cadeia pode passar do que a sua integração tolera esperar. Use "async": true e busque o resultado depois.

Depois da execução

Resultado, PDF e detalhe.

Resultado

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/result/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Esta rota responde sempre 200 — inclusive enquanto a execução roda, com status "running" e results vazio.

PDF

São dois passos. O primeiro devolve um JSON com a URL assinada, válida por 15 minutos:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Baixar o arquivo

curl -L "<url do passo anterior>" -o consulta.pdf

A URL assinada baixa sem cabeçalho de autenticação. Se preferir receber os bytes direto na chamada autenticada, use ?inline=true:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/?inline=true \
  -H "Authorization: Bearer psk_live_xxxx..." \
  -o consulta.pdf

Antes de a execução terminar, a rota responde 409 com code: "pdf_pending".

Detalhe da execução

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/ \
  -H "Authorization: Bearer psk_live_xxxx..."

É o mesmo dado que o painel mostra: status, results, result_available e o que foi cobrado (customer_charge, com o estorno quando houver).

O resultado vive 24 horas

Depois disso, /result/ e /pdf/ respondem 410 com code: "result_expired" e a consulta precisa ser executada de novo. O detalhe (GET /executions/<id>/) continua respondendo, com results vazio.

Preço

Por execução, no momento em que ela começa.

R$ 2,90 por execução, debitado do seu saldo ao iniciar (ou lançado na fatura, em conta pós-paga).

Execução que termina em failed ou invalid tem o valor estornado integralmente. Quando o saldo não cobre o preço, nada é cobrado — a chamada devolve 422 com insufficient_balance.

Depois da execução

Resultado, PDF e detalhe.

Resultado

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/result/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Esta rota responde sempre 200 — inclusive enquanto a execução roda, com status "running" e results vazio.

PDF

São dois passos. O primeiro devolve um JSON com a URL assinada, válida por 15 minutos:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Baixar o arquivo

curl -L "<url do passo anterior>" -o consulta.pdf

A URL assinada baixa sem cabeçalho de autenticação. Se preferir receber os bytes direto na chamada autenticada, use ?inline=true:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/?inline=true \
  -H "Authorization: Bearer psk_live_xxxx..." \
  -o consulta.pdf

Antes de a execução terminar, a rota responde 409 com code: "pdf_pending".

Detalhe da execução

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/ \
  -H "Authorization: Bearer psk_live_xxxx..."

É o mesmo dado que o painel mostra: status, results, result_available e o que foi cobrado (customer_charge, com o estorno quando houver).

O resultado vive 24 horas

Depois disso, /result/ e /pdf/ respondem 410 com code: "result_expired" e a consulta precisa ser executada de novo. O detalhe (GET /executions/<id>/) continua respondendo, com results vazio.

Depois da execução

Resultado, PDF e detalhe.

Resultado

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/result/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Esta rota responde sempre 200 — inclusive enquanto a execução roda, com status "running" e results vazio.

PDF

São dois passos. O primeiro devolve um JSON com a URL assinada, válida por 15 minutos:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Baixar o arquivo

curl -L "<url do passo anterior>" -o consulta.pdf

A URL assinada baixa sem cabeçalho de autenticação. Se preferir receber os bytes direto na chamada autenticada, use ?inline=true:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/?inline=true \
  -H "Authorization: Bearer psk_live_xxxx..." \
  -o consulta.pdf

Antes de a execução terminar, a rota responde 409 com code: "pdf_pending".

Detalhe da execução

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/ \
  -H "Authorization: Bearer psk_live_xxxx..."

É o mesmo dado que o painel mostra: status, results, result_available e o que foi cobrado (customer_charge, com o estorno quando houver).

O resultado vive 24 horas

Depois disso, /result/ e /pdf/ respondem 410 com code: "result_expired" e a consulta precisa ser executada de novo. O detalhe (GET /executions/<id>/) continua respondendo, com results vazio.

Depois da execução

Resultado, PDF e detalhe.

Resultado

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/result/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Esta rota responde sempre 200 — inclusive enquanto a execução roda, com status "running" e results vazio.

PDF

São dois passos. O primeiro devolve um JSON com a URL assinada, válida por 15 minutos:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Baixar o arquivo

curl -L "<url do passo anterior>" -o consulta.pdf

A URL assinada baixa sem cabeçalho de autenticação. Se preferir receber os bytes direto na chamada autenticada, use ?inline=true:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/?inline=true \
  -H "Authorization: Bearer psk_live_xxxx..." \
  -o consulta.pdf

Antes de a execução terminar, a rota responde 409 com code: "pdf_pending".

Detalhe da execução

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/ \
  -H "Authorization: Bearer psk_live_xxxx..."

É o mesmo dado que o painel mostra: status, results, result_available e o que foi cobrado (customer_charge, com o estorno quando houver).

O resultado vive 24 horas

Depois disso, /result/ e /pdf/ respondem 410 com code: "result_expired" e a consulta precisa ser executada de novo. O detalhe (GET /executions/<id>/) continua respondendo, com results vazio.

Preço

Por execução, no momento em que ela começa.

R$ 11,90 por execução, debitado do seu saldo ao iniciar (ou lançado na fatura, em conta pós-paga).

Execução que termina em failed ou invalid tem o valor estornado integralmente. Quando o saldo não cobre o preço, nada é cobrado — a chamada devolve 422 com insufficient_balance.

O corpo, os blocos e os status.

O corpo é o envelope { id, status, results }, com results indexado pelo slug do bloco.

Bloco opcional ausente não é erro. Fornecedor indisponível ou lento aparece como status: "failed" no corpo de um 200 — nunca como 502 ou 504 nesta forma de resposta.

Quando o resultado chega.

Este template responde 200 com o resultado no corpo. Para não esperar, mande "async": true e receba 202 na hora.

15 s
Teto do servidor
180 s

O teto é da conexão, não da cadeia: passando dele o servidor corta a resposta e a chamada volta sem o resultado. A execução não para — ela termina do nosso lado, e a cobrança continua de pé (o estorno só vem quando o desfecho é failed ou invalid).

Depois da execução

Resultado, PDF e detalhe.

Resultado

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/result/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Esta rota responde sempre 200 — inclusive enquanto a execução roda, com status "running" e results vazio.

PDF

São dois passos. O primeiro devolve um JSON com a URL assinada, válida por 15 minutos:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Baixar o arquivo

curl -L "<url do passo anterior>" -o consulta.pdf

A URL assinada baixa sem cabeçalho de autenticação. Se preferir receber os bytes direto na chamada autenticada, use ?inline=true:

  -H "Authorization: Bearer psk_live_xxxx..." \
  -o consulta.pdf

Antes de a execução terminar, a rota responde 409 com code: "pdf_pending".

Detalhe da execução

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/ \
  -H "Authorization: Bearer psk_live_xxxx..."

É o mesmo dado que o painel mostra: status, results, result_available e o que foi cobrado (customer_charge, com o estorno quando houver).

O resultado vive 24 horas

Depois disso, /result/ e /pdf/ respondem 410 com code: "result_expired" e a consulta precisa ser executada de novo. O detalhe (GET /executions/<id>/) continua respondendo, com results vazio.

Depois da execução

Resultado, PDF e detalhe.

Resultado

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/result/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Esta rota responde sempre 200 — inclusive enquanto a execução roda, com status "running" e results vazio.

PDF

São dois passos. O primeiro devolve um JSON com a URL assinada, válida por 15 minutos:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/ \
  -H "Authorization: Bearer psk_live_xxxx..."

Baixar o arquivo

curl -L "<url do passo anterior>" -o consulta.pdf

A URL assinada baixa sem cabeçalho de autenticação. Se preferir receber os bytes direto na chamada autenticada, use ?inline=true:

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/pdf/?inline=true \
  -H "Authorization: Bearer psk_live_xxxx..." \
  -o consulta.pdf

Antes de a execução terminar, a rota responde 409 com code: "pdf_pending".

Detalhe da execução

curl
curl -X GET https://api.prismafy.com.br/api/v1/executions/<id>/ \
  -H "Authorization: Bearer psk_live_xxxx..."

É o mesmo dado que o painel mostra: status, results, result_available e o que foi cobrado (customer_charge, com o estorno quando houver).

O resultado vive 24 horas

Depois disso, /result/ e /pdf/ respondem 410 com code: "result_expired" e a consulta precisa ser executada de novo. O detalhe (GET /executions/<id>/) continua respondendo, com results vazio.

Preço

Por execução, no momento em que ela começa.

R$ 1,00 por execução, debitado do seu saldo ao iniciar (ou lançado na fatura, em conta pós-paga).

Execução que termina em failed ou invalid tem o valor estornado integralmente. Quando o saldo não cobre o preço, nada é cobrado — a chamada devolve 422 com insufficient_balance.
